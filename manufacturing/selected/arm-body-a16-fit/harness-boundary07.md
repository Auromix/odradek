# A16 内走线与末端接口边界

这一版机械试配保留双相机、末端供电和控制的服务空间，尚未发行通电线束。以下区分实体中存在的通道与仍需选型/验证的线材，不把空包络当成已经装好的电缆。

| 段 | 当前机械空间 | 必须进一步验证 |
| --- | --- | --- |
| B06到J1 | Ø56底座出口；R101中孔；R102/R103两条6×14圆端槽，R55、55/235° | 可穿过的真实插头/线径、护边、根部转动服务环；所有电机均不能假定中空 |
| J1外围 | 两条4×10空包络，中心线两弯R18.75，之后R55.5上行 | 仅J1=0静态分配；选中线材的真实动态弯曲半径和48V载流未验证 |
| 上臂管 | 20×40×2管内16×36，当前Ø12直段Z11避开横向防压套 | 真实电源/CAN/双同轴分束、拉线顺序、固定与张力；新鞍座不穿入管内 |
| 前臂 | 同截面55长管，Ø12直段；罩固定在后脊 | 肘部与腕部之间完整接续、与原厂出线口/锁扣的余长与服务环 |
| J5/J6/J7 | 罩上现有服务窗口、原J7外围路由及接口顶侧空间 | 不存在贯穿电机的通孔；实际插头、绕轴余长和连续roll约束须按实物设计 |
| 裸臂工具面 | J7局部X110法兰、IF107及301/302/303服务结构保留 | 完成双相机同轴、工具电源与控制的最终连接器、引脚、屏蔽和防误插；四瓣头独立 |

底座源接口仍是：48V Phoenix1720466/1718481、双50Ω SMA Amphenol132170、EtherCAT专用RJ45直通，以及底座自己的灯控电路。**灵足原生CAN不能接到这只EtherCAT专用RJ45并当成EtherCAT从站。** 不修改底座针脚、不混用普通PC以太网与电机总线。

优先保持普通原生CAN控制链，由外置盒的CAN控制器/计算机完成周期控制，个人Ubuntu PC通过盒子的普通网络/开发接口访问。确需EtherCAT时要使用真正的网关并验证延迟、故障和使能链；目前没有把未选网关偷偷计入接口。CAN的对外物理出口仍需与底座源设计明确协同，不能据此版直接订制完整接线板。

以1Mbit/s、29位ID、每轴一条8字节命令及一条8字节反馈作预算，7轴每周期14帧，按每帧160bit含最坏填充和间隔估算约2.24ms。单总线1kHz目标不可据此保证；250Hz可作为早期带负载测量的通信设计起点，仍需实际总线占用、附加帧、抖动和内环行为验证。此预算不证明实时控制已经合格。

帧制式依据[CiA CAN CC说明](https://can-cia.org/can-knowledge/can-cc)和[CiA术语表](https://can-cia.org/cia-groups/cia-glossary-of-terms)，160bit为本项目保守长度预算，不是厂家控制周期承诺。外置盒可继续评估[PEAK PCAN-USB FD](https://www.peak-system.com/products/hardware/external-pc-interfaces/pcan-usb-fd/)这一类隔离USB-CAN适配器；并不改变灵足总线制式，也不解决底座出口。具体Ubuntu内核/驱动须按[厂家当前Linux支持](https://www.peak-system.com/fileadmin/media/linux/index.php)核对，不把USB接口的存在当成实时循环合格。

双GMSL/GMSL2仍为独立50Ω同轴，被动接口不解码视频；外置盒承担接收/解串和上位机数据导出。PoC电压/电流、相机与解串器型号未定，因此不能把同轴口当成已完成相机供电。末端供电电压/峰值电流也须由独立头部模块合同确定，不从48V电机母线直接推断。

根部4×10包络和R18.75弯不能保证一套合格的48V大电流线束；若真实线径/弯曲半径装不下，需要调整普通槽孔/外围走线空间并重新检查根罩。原型先做断电穿线板和量规验证，再做七轴全过程手动试动，最后完成限流、电源保护、回生、接地/屏蔽、视频误码和循环寿命试验。
