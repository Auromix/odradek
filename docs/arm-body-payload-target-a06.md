# A06：桌面机械臂负载对标与目标建议

日期：2026-10-02。本轮用户要求从J7向根部计算，并重新核对桌面机械臂的负载定位。**已确认要求仍为2 kg净工件、另加可拆头部、肩至任务TCP约700 mm。** 以下建议待用户选择，不直接改变结构参数或采购选型。

## 结论

在本轮核查的产品中，轻量研究机械臂有1.5 kg档，商用桌面协作臂有2 kg、5 kg档；这些样本不代表市场统计分布。它们对工具计重、重心与保持时间的定义不同，不能只比较宣传的公斤数。

本项目的2 kg是工件净重。加上尚未冻结、研究范围为0.8～1.5 kg的四瓣头，工具侧总质量达到**2.8～3.5 kg**，还需明确转接件和随动线束的计重归属。因此当前目标接近需要核对3 kg以上工具侧载荷的方案，而非直接对标“2 kg级机械臂”。

**2 kg净工件并非不合理，但对细长、灵动、七轴QDD桌面宠物是较有压力的目标。** 当前候选组合的计算余量紧张，也不能据此推出所有2 kg方案都会笨重：末端与腕部减重、缩短悬伸、关节重新分配仍可迭代。

## 方舟无限：目前可以借鉴什么

ARX X5的原厂SDK明确有六个本体关节和单独夹爪控制，采用CAN入口；默认重力补偿末端质量只包含夹爪，增加相机后要修改末端质量参数。这支持我们把灯瓣、相机、屏幕、驱动和壳体全部纳入载荷模型。来源：[固定版本ARX5 SDK说明](https://github.com/ARXroboticsX/ARX5_beta/blob/6768e886935c7a8a368e4dc29adfe10a8b7ca473/readme-CN.md)。

本轮官方网页、SDK、URDF与演示材料不足以闭合某一代X5的额定负载、峰值持续时间、臂展端点、整机自重和重心包络。**这表示本次公开证据不足，不表示产品能力不足。** 不把演示抓取或可调重力补偿参数视作持续承载证明。详细代际与来源见[ARX核验记录](engineering/sources/arm-a06-arx-research.md)。

## 我们自己的计算给出的信息

计算使用A05候选关节位置与目录质量，加上1.5 kg头部和1.4 kg结构预算。关节合计5.612 kg，臂体加头约8.512 kg，不含工件与固定底座；这是预算模型，尚非CAD质量或实物自重。详见[从J7到J1的回算](arm-body-loads-a06.md)。

| 工况 | 计算结果 | 对选型的含义 |
|---|---|---|
| J7，头1.5 kg＋工件2 kg，两者质心同轴，水平伸展 | 驱动重力矩0，J7原点横向弯矩3.826 N·m | 需要分别设计roll驱动与输出支承，不能因驱动重力矩为0就判定可以缩小关节 |
| J7，2 kg工件质心沿局部Y偏50 mm | 额外roll重力矩0.981 N·m | 工件重心和头部真实偏心要与质量一起定义；大灯瓣的转动惯量尚未加入 |
| 2 kg净工件、参考伸展，全臂质量预算 | J2 36.44 / J4 18.70 / J5 8.87 N·m | 对比候选目录40 / 20 / 11 N·m，静态余量已紧张；不是热稳态或动态通过判定 |
| 同一质量预算、姿态样点扫描 | J3样点最大19.21 N·m，对比目录20 N·m | 上臂roll也可能受重力限制；这只是有限样点最大值，不是全域上界 |
| 同一硬件和头部，改算1 kg净工件、参考伸展 | J2 29.57 / J4 14.29 / J5 6.23 N·m | 参考姿态负担下降，但需要重新扫描、计算动力学和热工况，不能直接宣布1 kg已额定通过 |

2 kg降到1 kg时，现有硬件质量不会自动下降。只有继续迭代腕部、连杆和上游关节，才能把减少的载荷转化为更轻的本体。

## 本轮只建议确认一个取舍

**按桌面宠物的定位，我倾向把第一版常用工件净重设为1 kg候选设计点**，保留700 mm肩至TCP和七轴方向；2 kg留作后续特定任务的验证目标，不预先承诺峰值时长或可达区域。选这个方向后，仍先核对头重、J7支承/偏心/惯量，再回传到J6和J5；不会立即采购更小电机。

如果2 kg是第一版实际操作任务的硬要求，则保持原目标，继续从头与腕部减重、缩短工具悬伸和调整关节组合入手，接受可能更大的关节和更高本体质量。现有计算还不足以给出确定的最终重量，也不建议简单把所有电机放大。

无论选哪一项，下一步均需把载荷写成“质量＋质心范围＋任务姿态与动作”，后续再补保持时间和热条件。**待确认的是第一版常用净工件目标；当前权威要求仍为2 kg。**
