# Odradek 注意力与灯光行为草案

状态：候选设计，待原型验证与评审；不是已批准规格或已实现能力。

目标是让人读懂“它在关注什么、是否准备行动”。机械朝向、照明与灯瓣表情应表达同一意图，避免仅靠不停运动制造存在感。

## 状态与转移

| 状态 | 候选行为 | 转移依据 |
| --- | --- | --- |
| **Rest 休息** | 本体保持安静姿态，灯瓣收拢，以柔和漫射光表达待机；是否呼吸可配置 | 收到有效任务或可靠目标后进入 Notice |
| **Notice 注意** | 光学头朝向目标，灯瓣小幅舒展，让关注方向可读；不立即执行抓取 | 目标持续有效且任务允许时进入 Inspect；失效则回 Rest |
| **Inspect 观察** | 按视觉任务需要保持或调整观察角度，探照灯照向工作区域；漫射灯瓣辅助表达观察状态 | 观察条件满足后进入 Task；任务取消或目标失效则停止推进 |
| **Task／Park 操作／停放** | Task 优先稳定照明与工具净空，暂停可能干扰操作的张合和呼吸；Park 按可行路径收拢本体与灯瓣 | 操作结束后进入停放或待机；停放须经运动包络验证 |

## 三类控制各司其职

探照灯提供有方向的任务照明；漫射灯瓣提供低强度状态表达，两者独立控制，不能用亮度呼吸替代所需照度。七轴负责观察与操作姿态，灯瓣负责局部张合；控制通道解耦，由同一任务状态协调。本体的关注动作与灯瓣张合分别规划，避免相互补偿造成无意移动。

若后续采用感知驱动，目标须有有效性与置信依据；置信不足或目标丢失时停止追随，回到已知姿态或等待新指令，并通过明确状态反馈降级。默认不持续扫描人脸；关注对象来自当前任务或用户明确选择。

表达状态随真实任务状态变化，不用预演灯效暗示已经识别或锁定目标。任务执行中收到新的关注请求时，应先判断是否允许切换；需要保持抓取或定位时保留当前姿态，待合适节点响应。此处尚未定义感知算法和控制实现。

B FRAME 暂探索三条腕背狭长灯瓣与夹爪上方中央光学头，手指净空优先。张合频率、角度、呼吸节奏和亮度均不预设数值；后续原型测量可读性、成像干扰、眩光与任务净空，再确定参数及转移条件。
